# v0.3 — core tool usability (level-matched auditioning, rig knobs, BLEND, undo)

Source: the user's hand test of v0.2 in Logic (build cdb4b9a, 2026-10-06). User decision: the core tone
tool comes first; separation / play-along is deferred (HANDOFF). Owner: dsp-engineer; reviewer audits
every task. Hard rules in CLAUDE.md apply in full. No new art (the user designs the UI); if a fix needs art,
propose it in the report.

User findings this phase answers (verbatim where useful):
- "We need the presets to be level matched, and ideally everything, so that auditioning is actually doable."
  "Different presets are different volumes, and need to be consistent or close."
- Rig editor: "All knobs on the rig editor are very hard to turn, nearly impossible."
- BLEND: "you have to enable blend in the rig section before you can turn it up"; "when you turn it on from
  the rig section a boost pedal opens but not a second amp, nothing on the knob."
- Undo: works for the BLEND fill only; "if you add more pedals it doesn't work."
- Gain steps: "not sure exactly which preset or capture to open to see" them.

## Task A (first) — rig-editor knobs are nearly impossible to turn

Root-cause before fixing. The rig-editor `PresetKnob` (`plugin/src/rig/RigWidgets.*`) wraps the same
`skin::FilmstripKnob` (250 px for full range) as the main-page knobs, which the user says work, so the
suspects are in the wrapper: the 4 Hz editor refresh (or a rebuild after each apply) writing the model value
back into the knob while it is being dragged; an apply that triggers a full engine rebuild per mouse move; a
parent intercepting the drag; a range or skew that makes most of the travel inaudible. Report the cause with
file:line.

Fix so every rig-editor knob drags exactly like a main-page knob (vertical drag, full range in 250 px, shift for
fine, double-click resets, wheel works) and is never overwritten while the mouse is down. Rebuild-heavy
parameters apply on a short debounce during the drag and once on mouse-up; no audio dropouts while dragging.
Tests (mouse-driven, like `test_live_controls.cpp`): for every PresetKnob type, a 250 px drag sweeps min to max;
a refresh tick during a drag does not move the knob; the model value at mouse-up equals the knob value.

## Task B — level-matched auditioning (presets, captures, A/B)

Goal: switching presets, captures or A/B never makes you judge "louder = better".

1. **Preset loudness normalisation.** Every preset gets an output trim that brings it to one loudness target
   on a fixed reference input: the built-in held-out DI excerpt the export already uses (`DI_BUILTIN`), played
   through the full chain incl. cab, post EQ and bus comp, measured as BS.1770 integrated loudness (reuse the
   10.1 level-match code). Target: **−18 LUFS** (state it in `docs/PRESET_SCHEMA.md`). Stored as
   `output.autoTrimDb` (schema version bump, old files read), applied after the user's OUTPUT knob.
   - Computed on a background thread at load when missing or stale (hash of the parts of the preset that affect
     level), never on the audio thread; until known, trim 0 and the LAT/CPU chip area says "LEVEL …".
   - Recomputed when the rig changes (debounced, background); the knob the user is turning never jumps — the
     new trim ramps over ≥ 200 ms.
   - Committed presets (`presets/**`) get their trims committed (generated by a script, rerunnable).
   - A **LEVEL MATCH** toggle (settings, default ON, saved as a setting not in the preset). OFF = today's levels.
     NAM export always uses the un-trimmed chain (the trim is a plain gain; state it).
2. **Capture audition.** Swapping a capture in a slot (capture browser preview and commit, gain-ladder rungs
   excluded — they already crossfade) applies a per-slot make-up so the slot's output loudness on the reference
   DI is unchanged; stored per slot in the preset.
3. **A/B** compares at matched loudness when LEVEL MATCH is on.

Acceptance: render every committed preset on the reference DI with LEVEL MATCH on: all within ±0.5 LU of
−18 LUFS (test). Same for A/B pairs and a capture swap in a slot (±0.5 LU). Defaults bit-identity is *not*
required for this task (the trim changes output level by design), but with LEVEL MATCH off every committed
preset renders bit-identical to cdb4b9a (golden test).

## Task C — BLEND works from the BLEND knob, and the body amp actually appears

1. Turning the BLEND knob off full SAW on a preset whose path B is off **enables the blend topology itself**
   (same code path as the rig section's switch, one undo step), so the user never has to visit the rig section.
   Turning BLEND back to full SAW does not delete path B.
2. The BLEND fill adds the boost **and** a body amp. Find why the user got only the boost: pool empty, no cached
   high-gain capture, the shortlist resolve not triggered or failing silently, or the amp block present but
   not shown on the head. Fix the cause. While the amp capture downloads, the body head reads
   "BODY AMP DOWNLOADING… (name)"; on failure it reads why (not logged in to TONE3000, network, no capture)
   with the one action that fixes it. Never a silent boost-only path.
3. The body head's knobs bind to the new amp as soon as it is loaded.

Tests: BLEND knob from 0 → 0.5 on a SAW-only preset enables blend and fills B (mouse-driven); with an empty
pool and a fake resolve tool, B gets the shortlist amp and the head shows the downloading → ready states;
with a failing tool the head shows the failure reason.

## Task D — undo / redo for every rig edit

Generalise v0.2's `RigController::undo` to all rig edits: add / remove / reorder / bypass a block, swap a
capture, change a block's parameters (one step per gesture: mouse-down to mouse-up), EQ edits, cab / mic,
topology and BLEND fill, preset load, apply-match. Cmd/Ctrl+Z undo, Cmd/Ctrl+Shift+Z redo, 64 steps, cleared
on preset load only if the user confirms nothing (preset load itself is undoable). Host-automated parameter
changes are not recorded. Existing overlay rules for Cmd+Z stay. Tests: each edit kind undoes and redoes to
the exact preset; a knob drag is one step; 65 edits keep the last 64.

## Task E — show where gain steps exist

- Each amp head shows a small "STEPS n" tag (text only, existing skin) when its capture has a gain ladder,
  and "STEPS —" when it was checked and has none; nothing while unknown.
- The capture browser marks captures whose pack has a ladder.
- Report: list which Classic / style / matched presets' amps have ladders today (run the ladder tool on each
  amp tone id), so I can tell the user which preset to open. If none do, propose one shortlist amp that does.
